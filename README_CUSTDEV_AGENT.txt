# 🤖 SYSTEM CONTEXT & AGENT INSTRUCTIONS: Pitchy Custdev Feature

## 📌 О проекте (Project Overview)
Этот репозиторий содержит микросервис — **инструмент для AI-кастдева (ранее MiroFish)**. 
Он будет работать как отдельный субдомен для основного продукта **Pitchy**. 
Система анализирует документы, строит онтологию через LLM (RouterAI), сохраняет ее в графовую базу Neo4j и генерирует отчеты.

## 📂 ИСТОЧНИК ДИЗАЙНА (REFERENCE SOURCE) — КРИТИЧЕСКИ ВАЖНО!
В корне проекта находится папка `pitchy_reference/`. В ней лежат исходники основного сайта Pitchy. 
Это твой **единственный и абсолютный эталон** дизайн-системы.

**Твои строгие правила работы с эталоном:**
1. **Read-Only:** Никогда не редактируй файлы внутри `pitchy_reference/`. 
2. **Изоляция:** Эта папка добавлена в `.gitignore`. Исходники оригинального Pitchy не должны попасть в коммиты этого репозитория.
3. **Анализ и Копирование:** Внимательно изучи `tailwind.config.js`, глобальные стили и UI-компоненты внутри `pitchy_reference/`. Копируй оттуда фирменные цвета, шрифты, тени, скругления и классы кнопок/инпутов, перенося их в нашу рабочую папку `frontend/`.

## 🛠 Архитектура и Стек (Tech Stack)
Рабочий проект (кастдев), который ты должен редактировать, разделен на две части:
1. **Frontend (Папка `frontend/`):** Vue 3 (Composition API), Vite, Tailwind CSS. Работает локально на порту `3000`.
2. **Backend (Папка `backend/` или корень):** Python, Flask/FastAPI, OASIS Agents, интеграция с RouterAI. Работает на порту `5001`.
3. **Database:** Neo4j (Docker).

## 🎯 Твоя главная задача (Mission)
Твоя цель — **полностью переработать UI/UX рабочей папки `frontend/`**, чтобы этот микросервис стал визуально неотличим от основного сайта Pitchy (опираясь на эталон `pitchy_reference/`). 

## 🛑 СТРОГИЕ ПРАВИЛА (STRICT RULES - DO NOT BREAK)

1. **НЕ ТРОГАЙ ЛОГИКУ БЭКЕНДА И API:**
   - Ни в коем случае не меняй эндпоинты в файлах, которые делают запросы к бэкенду (например, `/api/upload`, `/api/generate`).
   - Не ломай логику сохранения состояния проекта (Project ID) и механизмы опроса статуса (polling).

2. **ТОЛЬКО TAILWIND CSS:**
   - Полностью удаляй старые блоки `<style scoped>` и кастомный CSS из `.vue` файлов в `frontend/`.
   - Используй исключительно utility-классы Tailwind CSS, подтягивая их из конфигурации Pitchy.

3. **СОХРАНЯЙ ГРАФОВУЮ ЛОГИКУ:**
   - Отрисовка интерактивного графа (узлы и связи) — это ядро системы. Визуальную оболочку интерфейса вокруг графа можно менять, но логику библиотеки, которая рендерит сам граф, ломать нельзя.

4. **КОМПОНЕНТНЫЙ ПОДХОД:**
   - Если видишь огромный файл `MainView.vue`, разбивай его на мелкие переиспользуемые UI-компоненты (например, `FileUpload.vue`, `GraphStatus.vue`, `ReportView.vue`) в папке `frontend/src/components/`.

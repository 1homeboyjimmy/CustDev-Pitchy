# Универсальная подготовка к синтетическим кастдев-интервью

Вход — произвольный продуктовый вопрос и доступное описание проекта.
Основное назначение кастдева — проверка востребованности продукта; исследование
отдельной функции или внедрения является частным применением того же процесса.
Режимов исследования и переключателей нет. Не требуется, чтобы задача
касалась рынка, покупки или бюджета: это может быть изменение интерфейса,
внедрение инструмента, реакция разных групп или исследование потребности.

## Поток данных

1. Планировщик выделяет цель, предлагаемое изменение, решение, затронутые
   группы, роли, текущую ситуацию и неизвестные параметры. Существующие
   поисковые слоты получают предметные вопросы и ожидаемые доказательства.
   Официальные сайты, документация, исследования и обсуждения доступны наравне.
2. Провайдер поиска сохраняется. Scrapy читает HTML, таблицы, PDF и социальные
   обсуждения; X продолжает использовать уже настроенный официальный API.
3. Отдельный вызов модели извлекает утверждения из отобранных фрагментов
   каждой страницы. Сервер принимает цитату только если она действительно
   содержится в указанном фрагменте. Сохраняются строка/раздел, страница PDF
   или комментарий, авторская роль и география при наличии подтверждения.
4. Сводка строится по утверждениям: выводы с ссылками на цитаты, условия,
   противоречия, неизвестное, затронутые группы, гипотезы и нейтральные вопросы.
   Без подтверждения вывод помечается пробелом; расчёты и синтетические примеры
   не считаются эмпирическим подтверждением.
5. При подготовке симуляции сохранённый исследовательский контекст передаётся
   генератору персонажей и конфигурации. Гипотезы не являются готовыми ответами:
   персонаж вправе возражать, отказаться или не испытывать предполагаемой проблемы.
6. Итог сопоставляет внешний контекст и синтетические интервью по исходному
   вопросу. Новые прогоны не показывают обязательную воронку покупательского
   спроса. Сохранённые старые прогоны остаются совместимыми.

## Границы выводов

- Публичные комментарии не являются репрезентативным опросом общества.
- Цитата проверяется на присутствие в материале; её интерпретация и
  классификация остаются модельными и видны пользователю для проверки.
- Сайт поставщика подтверждает заявленные функции/условия, а не спрос аудитории.
- Зарубежные сведения сохраняются как сравнительный опыт; неизвестную
  географию нельзя автоматически считать российской по домену или языку.
- Повторные свидетельства одного издателя не становятся отдельными покупателями.
- Синтетические интервью не повышают достоверность внешнего факта.

## Лимиты и отказы

Количество поисковых слотов, результатов, страниц, комментариев, чтений X API
и общий таймаут оставлены прежними. Из существующего времени аналитики
выделяется часть на извлечение утверждений. При сбое экстракции страницы
остаются доступны, но не становятся подтверждёнными фактами.

HTML сохраняет строки таблиц вместе с заголовками; PDF сохраняет номера страниц.
Прежний предел текста одного документа сохраняется. Усечённые материалы и
выборочные фрагменты явно отмечаются; полнота условий не гарантируется.
Сканы без текстового слоя и защищённые документы помечаются как недоступные
для извлечения. OCR для веб-PDF в этом изменении не добавляется.

Обход всех ссылок базы знаний и автоматическая загрузка первоисточников из
библиографии не добавлены: это потребовало бы отдельно согласовать бюджет
страниц. Найденный прямой URL PDF обрабатывается текущим сборщиком.

## Проверки

`backend/tests/test_research_semantics.py` проверяет универсальность запроса,
неподтверждённые цитаты и географию, различия цены/оплаты/синтетики,
подготовку интервью, табличные условия и PDF через callback Scrapy.
`backend/scripts/check_market_research.py --full --query 'вопрос'` проверяет
развёрнутую конфигурацию. По умолчанию используется вопрос о востребованности
сервиса автоматизации кастдева. Для проверки частного сценария можно передать,
например, вопрос о реакции на обязательную регистрацию на сайте.
